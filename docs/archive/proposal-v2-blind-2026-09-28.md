# 갈피 (Galpi) — 프로젝트 기획서 초안 v2

**읽을 책, 갈피가 안 잡힐 때** — 묻지 않고, 책갈피 카드로 먼저 만나게 한다

| 작성 | 기간 | 형태 | 상태 |
|---|---|---|---|
| 2026-09-28 | 2026-09-28 ~ 10-31 (5주) | 개인 프로젝트 | **초안 v2 — 검토 전** (v1 알라딘 기준안은 `archive/`) |

> **3줄 요약**
> 1. YES24는 이미 추천 입구가 두 개 있다 — 말로 물어보는 AI 챗봇 **크레마AI**, 재미로 하는 성향 테스트 **RBTI**. 직접 써보니 크레마AI는 **문장을 써야 하고 결과가 긴 글**이며, RBTI는 **유형과 책이 잘 이어지지 않는다**.
> 2. 그래서 **입력 없이, 제목과 표지를 가린 책갈피 카드를 한 장씩 넘기며 "궁금해요"를 고르고, 마지막에 골라둔 책만 공개해 나란히 비교**하는 웹 "갈피"를 만든다.
> 3. **블라인드(한 줄만 보여줄 때)와 공개(표지·제목까지 보여줄 때) 중 어느 쪽이 "궁금해요"와 YES24 클릭으로 더 이어지는지**를 직접 모은 이용자 행동 데이터로 측정해, YES24 추천 화면 설계에 쓸 근거를 만든다.

## 1. 누가 읽고, 무엇을 결정하나

| | |
|---|---|
| **고객** | YES24 추천 서비스 기획자 (크레마AI·RBTI Lab 담당) |
| **결정** | 추천한 책을 **어떻게 보여줘야** 사람들이 관심을 갖고 상품 페이지까지 가는가 — 제목·표지부터 보여줄지, 내용 한 줄로 먼저 만나게 할지 |
| **이 프로젝트가 주는 것** | 실제 이용자 행동으로 측정한 숫자 — 블라인드 vs 공개의 "궁금해요"율·YES24 클릭률, 목적이 있는 사람도 제목 없이 고르는지, 어떤 한 줄에 끌리는지 |

**왜 YES24인가** — YES24는 2026년 Open API를 열면서 "큐레이션", "애드온 링크로 수익 연결"을 활용 사례로 내세웠다. 외부 서비스가 YES24로 사람을 보내주길 바라는 구조라, 갈피가 그 모델에 맞는다. 도서 데이터도 YES24 API에서 받고, 약관상 YES24 상품 링크를 달아야 하므로 데이터와 고객이 하나로 맞는다. (알라딘은 Open API를 2026-10-30 종료한다.)

## 2. 문제 정의

### 2-1. YES24의 추천 입구 두 개 — 직접 써본 관찰 (2026-09-28)

상세: `teardown-crema-ai-2026-09-28.md`, `probe-crema-ai-2026-09-28.md` (캡처·원문 포함)

| | 크레마AI (chat.yes24.com) | RBTI Lab (rbti.yes24.com) |
|---|---|---|
| 방식 | AI에게 문장으로 질문 | 12문항 2지선다 → 16유형 강아지 캐릭터 |
| 잘하는 것 | 추천 품질이 높다. 조건(쪽수·가격·제외) 준수, 대화 맥락 유지, 없는 책은 없다고 답함 | 귀엽고 가볍다. 참여 38.5만 명 (단, 완료 시 YES상품권 500원 보상) |
| 관찰한 한계 | **문장을 써야 한다**. 답이 **26~83초** 걸린다. 결과가 **긴 글**이라 나란히 비교가 어렵다. 막연한 질문에도 되묻지 않고 베스트셀러로 간다 | **유형과 책이 약하게 이어진다** — 정반대 두 유형의 추천 8~9권 중 3권이 같았고, "학구파"에게 어린이 학습만화가 나왔다. **추천 이유가 없다**. 결과의 주인공이 책이 아니라 "나"다 |

두 입구 모두 **"책 자체를 만나는 재미"** 와 **"고른 책을 나란히 비교하는 화면"** 이 없다.

### 2-2. 과장하지 않는 것

- **이용자 불만으로 확인된 것이 아니다.** 크레마AI 사용 후기는 웹·블로그·커뮤니티에서 찾지 못했고, 구글 플레이 YES24 앱 리뷰 838건 중 크레마AI·RBTI 언급은 0건이다. 위 한계는 **직접 사용해 관찰한 것**이며, 갈피 실험으로 검증한다
- **책 고르기 어려움은 전체 성인에게 큰 장애가 아니다.** 국민독서실태조사 원자료(성인 5,000명, 가중)로 계산하면 "어떤 책을 읽을지 몰라서"는 9위, 1순위 응답 2.1%(2025)·2.6%(2023). 대상은 **"이미 읽으려고 온 사람"** 으로 좁힌다
- 알라딘 추천마법사(구매 이력 기반, 이력 없으면 추천 0권, 이유 없음) 분석은 **업계 공통 사례**로 참고한다 (`../../strategy/aladin-wizard-teardown-2026-09-28.md`)

### 2-3. 가설

| # | 가설 | 어떻게 확인하나 |
|---|---|---|
| H1 | 제목·표지를 가리고 **내용 한 줄로 먼저 만나면**, 공개했을 때보다 "궁금해요"가 늘어난다 | 블라인드 vs 공개 무작위 비교 |
| H2 | 그렇게 고른 책이 **YES24 상품 페이지 클릭**으로도 더 이어진다 (재미로만 끝나지 않는다) | 같은 실험의 YES24 클릭률 |
| H3 | 목적이 있는 사람은 블라인드여도 **제목을 먼저 보고 싶어 한다** | 🎯 카드의 [제목 바로 보기] 클릭 비율 |

결과가 가설과 반대여도 결론이다. 예: "블라인드는 궁금해요는 늘리지만 구매 클릭은 줄인다 — 재미까지만 작동한다."

## 3. 무엇을 만드나

### 3-1. 이용 흐름 — 입구는 둘, 출구는 하나

```
🎯 알고 싶은 게 있어요                   🍃 그냥 한 권 만나고 싶어요
   칩으로 고르기 (입력 없음)                가벼운 질문 몇 개 또는 기분 칩 (미정)
   무엇을: 데이터 분석 / 통계 / 습관 …
   수준: 처음 / 조금 / 실무
   어떤 책: 개념 쉽게 / 실습 많이 / 얇게
            ↓                                       ↓
   ─────────── 책갈피 카드 8장을 한 장씩 ───────────
   블라인드: 첫인상 한 줄 + 태그 3개      공개: 같은 카드 + 표지·제목
   (🎯 카드엔 [제목 바로 보기])
   → [패스] [궁금해요]
            ↓
   ─────────── "궁금해요"만 모아 공개 ───────────
   표지 · 제목 · 가격 · 쪽수 · 평점 · 추천 이유를 나란히 비교
   → [담아두기] [예스24에서 보기]
```

### 3-2. 설계 원칙

- **입력하지 않는다** — 칩을 누르는 것만으로 시작. 크레마AI처럼 문장을 쓰지 않는다
- **책이 주인공** — RBTI·밀리 성향 테스트처럼 "나는 어떤 유형"이 아니라, 책이 한 줄로 자기소개한다
- **첫인상 한 줄은 책에서 나온다** — 책소개·목차·줄거리에 있는 내용만 쓰고, 스포일러와 과장은 쓰지 않는다
- **마지막엔 반드시 비교** — 골라둔 책을 나란히 놓고 가격·분량·평점을 한눈에
- **책갈피처럼 들고 싶게** — 민음사 책갈피의 가볍고 친근한 분위기를 참고하되, **그림은 직접 만든다** (민음사 저작물은 쓰지 않는다)
- **리뷰는 판단하지 않는다** — 평점 숫자만 보여주고, 리뷰 원문은 YES24에서 본다. 갈피에 리뷰를 남기는 기능은 없다

### 3-3. 범위

- 책 **100~200권** 내외 — 🎯용(데이터 분석·통계·자기계발), 🍃용(에세이·소설 등 가볍게 읽을 책)
- 추천은 **태그 매칭**. 머신러닝 추천 모델은 만들지 않는다
- 분석이 목적이므로 **추천 알고리즘의 정교함은 목표가 아니다**

## 4. 데이터와 방법

### 4-1. 도서 데이터

| 항목 | 출처 | 비고 |
|---|---|---|
| 추천할 책 목록 | YES24 카테고리별 베스트·스테디셀러 + 정보나루 인기 대출 | 분야를 통째로 긁지 않고 **추천할 책만** 고른다 (YES24 약관) |
| 책소개·목차·줄거리 | YES24 상품 상세 | **첫인상 한 줄의 재료** |
| 가격·쪽수·평점·표지·상품 링크 | YES24 상품 상세 | 비교 화면 |
| 핵심 키워드 | 정보나루 | 태그 재료 (LLM이 지어내지 않도록) |
| 대체 | 카카오 책 검색 | YES24 장애 시 가격·표지 |

**YES24 약관 준수** (developers.yes24.com 공지·FAQ 원문 확인)
- 책 정보가 보이는 화면에 **예스24 출처 표기**, 상세·구매 영역에 **예스24 상품 링크**
- 서비스에 필요한 범위에서만 저장. **전체 도서를 모아 자체 DB로 쌓지 않는다.** 가격은 짧은 주기로 갱신
- API 키는 **서버에서만** 사용 (웹페이지 코드에 넣지 않는다)

### 4-2. 첫인상 한 줄 만들기

| 단계 | 담당 |
|---|---|
| 책소개·목차·줄거리를 주고 "제목·저자·출판사 없이, 이 책에 있는 내용만으로 한 줄" 초안 | LLM |
| 규칙 검사: 제목·저자명 포함 여부, 길이, 금지 표현 | Python |
| 전수 검수 — 사실과 다르거나 스포일러·과장이면 고친다 | 본인 |

Olist 때와 같은 원칙이다 — **LLM은 초안, 판단은 사람, 규칙은 코드.**

### 4-3. 이용자 행동 데이터 (직접 수집)

익명 식별자와 이벤트만 기록한다. 개인정보는 받지 않는다.

| 이벤트 | 속성 |
|---|---|
| `entry_selected` | 🎯/🍃, 유입 경로 |
| `chip_selected` | 질문, 선택값 |
| `card_shown` | 책 ID, 순서, **실험 조건(블라인드/공개)**, 한 줄 유형 |
| `title_peeked` | 책 ID (🎯의 [제목 바로 보기]) |
| `card_reacted` | 책 ID, 패스/궁금해요 |
| `reveal_viewed` | 공개된 책 ID 목록 |
| `book_saved` | 책 ID |
| `yes24_clicked` | 책 ID |

### 4-4. 분석 질문

**핵심 실험** — 이용자를 **블라인드 / 공개** 두 조건에 무작위로 나누고 비교한다 (H1, H2)
- 1차 지표: 카드당 "궁금해요" 비율
- 2차 지표: 이용자당 YES24 클릭 여부

**보조 질문**
- 퍼널: 입구 선택 → 칩 완료 → 카드 1장 → 8장 완주 → 공개 화면 → 담기 → YES24 클릭. 어디서 가장 많이 빠지나
- 8장 중 **몇 번째에서 그만두나** — 적정 카드 수
- 🎯 이용자의 **[제목 바로 보기] 비율** (H3)
- 어떤 한 줄(내용 요약형 / 상황형 / 질문형)에 더 끌리나
- 🎯와 🍃의 행동 차이

**통계적 한계를 먼저 적는다**
이용자 30~50명 규모에서는 조건 간 작은 차이를 검출하기 어렵다. 결과는 **차이의 크기와 신뢰구간**으로 보고하고 "유의하다/아니다"로 단정하지 않는다. 카드 단위 지표는 한 사람이 여러 장을 보므로 이용자 단위로 묶어 분석한다. 검출 가능한 최소 효과 크기를 사전에 계산해 적는다.
