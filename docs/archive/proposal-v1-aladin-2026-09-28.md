# 갈피 (Galpi) — 프로젝트 기획서 초안

**읽을 책, 갈피가 안 잡힐 때** — "지금 무엇을 알고 싶은지" 물어보고, 근거와 함께 책을 비교해 보여준다

| 작성 | 기간 | 형태 | 상태 |
|---|---|---|---|
| 2026-09-28 | 2026-09-28 ~ 10-31 (5주) | 개인 프로젝트 | **초안 — 검토 전** |

> **3줄 요약**
> 1. 알라딘 추천마법사를 직접 써보니, 사용자에게 **무엇이 필요한지 묻지 않고 과거 구매 이력으로만** 추천한다. 이력이 없는 분야는 추천이 0권이고, 추천 이유도 보여주지 않는다.
> 2. 그래서 **목적을 먼저 묻고 → 근거(책소개·핵심 키워드)와 함께 → 여러 권을 카드로 비교**하게 해주는 웹을 만들어, 데이터 분석·자기계발 입문자에게 배포한다.
> 3. 사용자가 실제로 **무엇을 보고 책을 고르는지**, 그리고 **추천 이유를 보여주는 것이 선택을 돕는지**를 직접 수집한 행동 데이터로 측정해, 온라인 서점의 추천 화면 설계에 쓸 근거를 만든다.

## 1. 누가 읽고, 무엇을 결정하나

| | |
|---|---|
| **고객** | 알라딘 추천마법사(온라인 서점 탐색·추천 화면) 기획자 |
| **결정** | 추천 진입을 "과거 이력 기반 목록"에서 **"목적 질문 → 비교 카드"** 로 바꿀 가치가 있는가. 바꾼다면 카드에 **무엇을** 보여줘야 하는가 |
| **이 프로젝트가 주는 것** | 실제 사용자 행동으로 측정한 숫자 — 질문 방식의 완주율, 카드 정보별 선택 기여, 추천 이유 유무에 따른 전환 차이 |

## 2. 문제 정의

### 2-1. 현재 방식: 알라딘 추천마법사는 묻지 않는다

2026-09-28 본인 계정으로 직접 사용해 확인했다 (상세: `../../strategy/aladin-wizard-teardown-2026-09-28.md`, 캡처 포함).

- **입력은 세 가지뿐** — 관심분야(분야 3단계 드롭다운), 구매 이력("가장 크게 반영됩니다"), '관심없어요'. 목적·수준·상황을 넣을 방법이 없다
- **분류에 목적이 없다** — 컴퓨터/모바일 하위에 "데이터 분석"이 없고, 입문/심화 같은 난이도 축도 없다
- **이력이 없으면 아무것도 없다** — 컴퓨터/모바일, 자기계발 모두 "고객님을 위해 준비된 추천 상품이 없습니다"
- **추천 이유가 없다** — 결과는 제목·가격·평점·배송이 나열된 상품 목록. 책끼리 비교하는 화면도 없다

> 한계: 계정 1개 관찰. 알라딘 구매 이력이 많은 사용자는 결과가 다를 수 있다. 이 프로젝트가 겨냥하는 것은 **이력이 적은 사용자, 새 분야를 시작하는 사용자**다.

### 2-2. 다른 서비스도 목적에서 출발하지 않는다

| 서비스 | 무엇에서 출발하나 |
|---|---|
| 밀리의서재 AI발견 | 랜덤 (카드 뒤집기) |
| 밀리의서재 성향 테스트 | 나의 성격 유형 → 한 권 지정 |
| 알라딘 추천마법사 | 구매 이력 + 관심분야 |
| 플라이북 (앱) | 성별·나이·기분·관심사 |
| 챗GPT에 질문 | 목적에서 출발하지만 **실제 책 정보에 근거하지 않고**, 존재하지 않는 책을 지어낼 수 있다 (→ 4-3에서 직접 측정) |

### 2-3. 문제의 크기 — 과장하지 않는다

국민독서실태조사 원자료(성인 5,000명, 가중)로 직접 계산하면, 독서를 어렵게 하는 이유 중 **"어떤 책을 읽을지 몰라서"는 9위, 1순위 응답 2.1%(2025)·2.6%(2023)** 다. 전체 성인에게 큰 장애는 아니다.

그래서 대상을 **"이미 읽으려는 사람 중, 목적을 갖고 책을 찾는 사람"** 으로 좁힌다. 실태조사는 안 읽는 사람까지 포함하므로, 독서자·전자책 이용자로 좁힌 재계산을 기획 확정 전에 추가한다.

## 3. 무엇을 만드나

### 3-1. 사용자 흐름

```
[진입] → [질문 3~4개] → [추천 카드 3~5권 나란히] → [카드 펼쳐보기] → [담기 / 알라딘에서 보기]
          무엇을 알고 싶은지     표지·제목·추천 이유 한 줄      책소개 요약·핵심 키워드
          지금 수준               난이도·분량·가격              [알라딘에서 리뷰 보기 →]
          읽을 수 있는 시간/분량  도서관 대출 횟수 (인기 지표)
```

- **먼저 묻는다** — 이력이 없어도 첫 방문에 결과가 나온다
- **이유를 보여준다** — "표본·평균·그래프를 일상 사례로 설명하는 통계 입문서"처럼 **책소개와 핵심 키워드에 근거한** 한 줄
- **나란히 비교한다** — 한 권 지정이 아니라 3~5권 중 사용자가 고른다
- **리뷰는 판단하지 않는다** — 갈피는 찾아주는 곳. 리뷰 원문은 알라딘에서 본다. 갈피에 리뷰를 남기는 기능은 없다
- **귀엽고 부담 없는 톤** — 민음사 책갈피처럼 가볍고 친근한 말투와 그림. 쇼핑몰이 아니라 "책 골라주는 친구"

### 3-2. 범위

- **분야 2개**: 데이터 분석(통계·파이썬 포함), 자기계발 — 둘 다 "목적이 있어서 읽는 책"이고, 본인이 많이 읽어 추천 품질을 직접 판단할 수 있다
- **도서 100권 내외** (분야별 50권)
- 추천 로직은 **태그 매칭**(목적·난이도·분량·스타일)으로 시작한다. 머신러닝 추천 모델은 만들지 않는다

## 4. 데이터와 방법

### 4-1. 도서 데이터

> **2026-09-28 확인**: 알라딘 Open API는 서비스를 종료한다 — 신규 인증키 신청 9/4 마감, 기존 이용자도 **10/30 종료** ([공지](https://blog.aladin.co.kr/openapi/popup/6695306)). 도서 데이터는 공공 API로 받고, 알라딘은 **링크 대상으로만** 쓴다 (ISBN 검색 주소, API 불필요).

| 항목 | 출처 | 방법 |
|---|---|---|
| 추천할 책 목록 | 도서관 정보나루 인기 대출 도서 (분야·연령별) | API 또는 웹 엑셀(키 불필요, 1,000건) |
| 제목·저자·책소개 | 정보나루 도서 상세 | API (하루 500건). 책소개는 **내용 요약형**이라 추천 이유 재료로 적합 |
| 핵심 키워드 + 가중치 | 정보나루 도서 키워드 | API — **태그의 재료.** LLM은 키워드·책소개에 있는 내용만 태그로 정리 |
| 대출 횟수 | 정보나루 | 평점 대신 인기 지표로 표시 |
| 쪽수·주제 | 국립중앙도서관 서지 API | API (공공데이터포털 자동 승인) — 분량 태그 |
| 가격 | 카카오 책 검색 API | 9/28 확인: 10권 중 10권 정가·판매가 있음 |
| 표지 | 카카오 책 검색 API | 응답의 원본 이미지 주소가 458px (정보나루 표지 200px, 카카오 썸네일 120px) |
| 목차 | **정보나루에 없음** (9/28 확인). 국중 서지 API 제공 여부 확인 | 없으면 쓰지 않는다. 추천 이유는 책소개·키워드 근거 |
| 리뷰 | 가져오지 않음 | 궁금한 사람은 알라딘 링크로 본다 |
| 태그 (목적·난이도·분량·스타일) | 본인 | 도메인 지식으로 직접 부여 |
| 추천 이유 한 줄 | 본인 작성 또는 LLM 초안 + 본인 검수 | LLM을 쓰면 **책소개·키워드에 있는 내용만** 근거로 쓰게 하고 검수 |

### 4-2. 사용자 행동 데이터 (직접 수집)

익명 식별자와 이벤트만 기록한다. 개인정보는 받지 않는다.

| 이벤트 | 속성 |
|---|---|
| `visit` | 유입 경로 |
| `question_answered` | 질문 번호, 선택값 |
| `cards_shown` | 노출된 책 ID·순서, 실험 조건 |
| `card_expanded` | 책 ID, 펼친 정보(책소개·키워드) |
| `review_link_clicked` | 책 ID — 알라딘 리뷰를 보러 나감 |
| `book_saved` | 책 ID |
| `aladin_clicked` | 책 ID |

### 4-3. 분석 질문

**핵심 질문 1개**
> 비교 카드에서 **추천 이유를 보여줄 때와 안 보여줄 때**, 담기·알라딘 클릭까지 가는 비율이 달라지는가

알라딘 추천마법사가 이유를 보여주지 않는다는 관찰(2-1)을 그대로 검증하는 실험이다. 사용자를 두 조건에 무작위로 나눈다.

**보조 질문**
- 퍼널: 진입 → 질문 완료 → 카드 → 펼침 → 담기 → 알라딘 클릭. 어디서 가장 많이 빠지나
- 사람들은 카드에서 **무엇을 보고** 고르나 — 책소개를 펼치나, 리뷰를 보러 나가나, 표지·가격만 보고 담나
- **추천 이유가 리뷰를 대신하는가** — 추천 이유를 보여준 조건에서 리뷰를 보러 나가는 비율이 낮아지는가
- 분야·수준별로 고르는 방식이 다른가

**비교 기준 — 챗GPT 측정**
같은 목적 질문 10개를 챗GPT에 던져 받은 추천을 알라딘에서 확인한다 — 국내 출간 여부, 저자·내용 정확성, 실제 책 정보에 근거한 추천인지 여부. **가정하지 않고 잰다.**

**통계적 한계를 먼저 적는다**
사용자 30~50명 규모에서는 두 조건의 작은 차이를 유의하게 검출하기 어렵다. 결과는 **차이의 크기와 신뢰구간**으로 보고하고, "유의하다/아니다"로 단정하지 않는다. 검출 가능한 최소 효과 크기를 사전에 계산해 적는다.
