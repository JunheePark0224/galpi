# 갈피 (Galpi) — 프로젝트 기획서 초안 v3

**읽을 책, 갈피가 안 잡힐 때** — 오래된 책 한 권을 펼치면, 장마다 나에게 맞는 책이 책갈피로 꽂혀 있다

| 작성 | 기간 | 형태 | 상태 |
|---|---|---|---|
| 2026-09-29 | 2026-09-28 ~ 10-31 (5주) | 개인 프로젝트 | **초안 v3 — 검토 전** (이전 버전은 `archive/`) |

> **갈피의 용도 (09-29 확정)** — **읽을 책이 정해지지 않은 사람이, 조건 몇 개만으로 나에게 맞는 책을 재미있게 만나게 해 주는 웹**
>
> | 하는 일 | 하지 않는 일 |
> |---|---|
> | 좁혀 준다 (막연함 → 맞는 책 몇 권) | 이미 아는 책·작가 찾기 (→ "예스24 검색을 이용해 주세요" 링크) |
> | 재미있게 만나게 한다 (책 펼치기·책갈피·밸런스 게임) | 리뷰·평점 쓰기 |
> | 이유를 보여준다 (나온 이유) | 구매, 독서 기록·완독 관리 |
> | 만난 책을 모은다 (내 책갈피 컬렉션) | AI와 대화로 상담 |
> | 결정은 서점으로 넘긴다 (예스24에서 보기) | 모든 책 목록 보여주기 |
>
> 새 기능 판단 질문: **"이게 뭘 읽을지 모르는 사람이 맞는 책을 재미있게 만나는 데 도움이 되나?"** 아니면 만들지 않고, 필요하면 예스24로 연결만 한다.

> **무엇을 만드는지(기능·화면·이벤트)는 `PRD.md`가 최신이다.** 결과 화면·보관·로그인은 PRD에서 바뀌었다.

> **3줄 요약**
> 1. YES24의 추천 입구 두 개를 직접 써보니, 크레마AI는 **문장으로 물어봐야 하고 결과가 긴 글**이며, 성향 테스트 RBTI는 **유형과 책이 잘 이어지지 않고 추천 이유가 없다**.
> 2. 그래서 **칩만 고르면 오래된 책 한 권이 나오고, 펼치면 첫 장에 내 상황이, 다음 장부터는 책 위로 꽂힌 책갈피 5개에 책 제목과 첫인상 한 줄이 적혀 있어 "궁금해요/패스"로 고르는** 웹 "갈피"를 만들어 배포한다.
> 3. **1단계로 실제 이용자를 모아 행동을 기록하고, 2단계로 데이터에서 찾은 문제 하나를 고쳐 전후를 비교**한다. 결과는 YES24 추천 화면 설계에 쓸 근거로 정리한다.

## 1. 누가 읽고, 무엇을 결정하나

| | |
|---|---|
| **고객** | YES24 추천 서비스 기획자 (크레마AI·RBTI Lab 담당) |
| **결정** | 추천한 책을 **어떻게 보여줘야** 사람들이 끝까지 보고, 관심을 갖고, 상품 페이지까지 가는가 |
| **이 프로젝트가 주는 것** | 실제 이용자 행동 기록 — 어디서 그만두는지, 몇 번째 책갈피까지 보는지, 어떤 책과 한 줄에 "궁금해요"가 몰리는지, 그리고 **하나를 고쳤을 때 무엇이 달라졌는지** |

**왜 YES24인가** — YES24는 2026년 Open API를 열면서 "큐레이션", "애드온 링크로 수익 연결"을 활용 사례로 내세웠다. 외부 서비스가 YES24로 사람을 보내주길 바라는 구조라 갈피와 맞는다. 도서 데이터도 YES24 API에서 받고, 약관상 YES24 상품 링크를 달아야 하므로 데이터와 고객이 하나로 맞는다. (알라딘은 Open API를 2026-10-30 종료한다.)

## 2. 문제 정의

### 2-1. YES24의 추천 입구 두 개 — 직접 써본 관찰 (2026-09-28)

상세: `teardown-crema-ai-2026-09-28.md`, `probe-crema-ai-2026-09-28.md` (캡처·원문 포함)

| | 크레마AI (chat.yes24.com) | RBTI Lab (rbti.yes24.com) |
|---|---|---|
| 방식 | AI에게 문장으로 질문 | 12문항 2지선다 → 16유형 강아지 캐릭터 |
| 잘하는 것 | 추천 품질이 높다. 조건(쪽수·가격·제외) 준수, 대화 맥락 유지, 없는 책은 없다고 답함 | 귀엽고 가볍다. 참여 38.5만 명 (단, 완료 시 YES상품권 500원 보상) |
| 관찰한 한계 | **문장을 써야 한다**. 답이 **26~83초** 걸린다. 결과가 **긴 글**이라 나란히 비교가 어렵다. 막연한 질문에도 되묻지 않는다 | **유형과 책이 약하게 이어진다** — 정반대 두 유형의 추천 8~9권 중 3권이 같았고, "학구파"에게 어린이 학습만화가 나왔다. **추천 이유가 없다**. 결과의 주인공이 책이 아니라 "나"다 |

두 입구 모두 **책을 하나씩 만나는 재미**와 **내 상황을 제대로 이해했는지 확인하는 단계**가 없다.

### 2-2. 과장하지 않는 것

- **이용자 불만으로 확인된 것이 아니다.** 크레마AI 사용 후기는 웹·블로그·커뮤니티에서 찾지 못했고, 구글 플레이 YES24 앱 리뷰 838건 중 크레마AI·RBTI 언급은 0건이다. 위 한계는 **직접 사용해 관찰한 것**이다
- **책 고르기 어려움은 전체 성인에게 큰 장애가 아니다.** 국민독서실태조사 원자료(성인 5,000명, 가중)로 계산하면 "어떤 책을 읽을지 몰라서"는 9위, 1순위 응답 2.1%(2025)·2.6%(2023). 대상은 **"이미 읽으려고 온 사람"** 으로 좁힌다
- 알라딘 추천마법사(구매 이력 기반, 이력 없으면 추천 0권, 이유 없음) 분석은 **업계 공통 사례**로 참고한다 (`../../strategy/aladin-wizard-teardown-2026-09-28.md`)

## 3. 무엇을 만드나

### 3-1. 이용 흐름

```
[처음 화면]
 🎯 알고 싶은 게 있어요                  🍃 그냥 한 권 만나고 싶어요
    칩으로 고르기                            가벼운 질문 몇 개 또는 기분 칩 (미정)
    무엇을: 데이터 분석 / 통계 / 습관 …
    수준: 처음 / 조금 / 실무
    어떤 책: 개념 쉽게 / 실습 많이 / 얇게
    (선택) 지금 상황 한 줄 적기
            ↓                                      ↓
[책 등장]  오래된 책 한 권이 나타난다 → 눌러서 펼치기
            ↓
[첫 장]    "당신이 찾는 책" — 고른 칩과 적은 한 줄이 그대로 적혀 있다 → [한 번 고치기]
            ↓  다음 장 펼치기
[책갈피 1~5장]
           장마다 책 윗부분으로 책갈피 하나가 꽂혀 나와 있다
           책갈피에: 책 제목 · 첫인상 한 줄 · [패스] [궁금해요]
            ↓
[마지막 장] "궁금해요"만 모아서 — 표지 · 제목 · 평점 · 가격 · 쪽수를 나란히
           → [담아두기] [예스24에서 보기]
           궁금해요가 0개면 → [다시 뽑기] [처음으로]
```

### 3-2. 설계 원칙

- **추천 기준은 사람이 정하고, 설명할 수 있다** — AI는 태그·한 줄 초안과 직접 쓴 말 분류만 한다. 어떤 책이 왜 나왔는지는 공개된 태그와 점수 규칙으로 설명되고, 태그는 사람이 따로 붙인 것과 비교해 검증한다 (09-29, 사용자가 크레마AI를 믿기 어려웠던 이유 — 선정 기준이 보이지 않고 AI가 알아서 고름)
- **입력은 칩으로** — 문장을 쓰지 않아도 추천이 나온다. 상황 한 줄은 선택 사항이고, **추천에는 쓰지 않고 첫 장에 그대로 보여주기만 한다** (문장을 해석하려면 AI가 필요해져 크레마AI와 같아지고, 만들 것도 늘어난다)
- **먼저 확인한다** — 첫 장에서 "이렇게 이해했어요"를 보여주고 한 번 고칠 수 있게 한다
- **책이 주인공** — "나는 어떤 유형"이 아니라, 책갈피에 책 제목과 그 책의 한 줄이 적힌다
- **제목은 가리지 않는다** — 제목을 보고 아는 책이면 바로 판단할 수 있게
- **첫인상 한 줄은 책에서 나온다** — 책소개·목차·줄거리에 있는 내용만 쓰고, 스포일러와 과장은 쓰지 않는다
- **막다른 길이 없다** — 궁금해요가 0개면 다시 뽑기나 처음으로
- **리뷰는 판단하지 않는다** — 평점 숫자만 보여주고, 리뷰 원문은 YES24에서 본다

### 3-3. 디자인 방향

- **따뜻하고 오래된 책** — 낡은 천 표지, 크림색 종이. 어둡고 무거운 마법서 느낌이나 종교적 상징(별 문양 등)은 쓰지 않는다
- **책갈피는 책 윗부분으로 꽂혀 나온다** — 실제 책갈피처럼 머리 부분이 책 위로 튀어나와 있고, 몸통에 제목·한 줄·버튼이 적힌다
- **민음사 책갈피처럼 들고 싶게** — 가볍고 친근한 분위기를 참고하되 **그림은 직접 만든다** (민음사 저작물은 쓰지 않는다)
- 책을 펼치고 장을 넘기는 **움직임**이 핵심 경험 — 휴대폰에서도 부드럽게

### 3-4. 범위

- 책 **100~200권** 내외 — 🎯용(데이터 분석·통계·자기계발), 🍃용(에세이·소설 등 가볍게 읽을 책)
- 추천은 **칩 → 태그 매칭**. 머신러닝 추천 모델은 만들지 않는다
- 한 번 펼칠 때 책갈피 **5개** (적정 개수는 데이터로 다시 확인한다. 더 보고 싶으면 [다시 뽑기]로 새 책 5권)

## 4. 데이터와 방법

### 4-1. 도서 데이터

| 항목 | 출처 | 비고 |
|---|---|---|
| 추천할 책 목록 | YES24 분야별 베스트·스테디셀러 + 검색 (`src/collect_candidates.py`) | 분야를 통째로 긁지 않고 **추천할 책만** 고른다 (YES24 약관) |
| 책소개·목차·줄거리 | YES24 상품 상세 | **첫인상 한 줄의 재료** |
| 가격·쪽수·평점·표지·상품 링크 | YES24 상품 상세 | 마지막 장 비교 |
| 핵심 키워드 | **YES24 목차·책소개** (09-29 변경) | 태그 재료. 정보나루 키워드는 새 책(🎯 후보 절반)에 없어 보조로만 |
| 대체 | 카카오 책 검색 | YES24 장애 시 가격·표지 |

**YES24 약관 준수** (developers.yes24.com 공지·FAQ 원문 확인)
- 책 정보가 보이는 화면에 **예스24 출처 표기**, 상세·구매 영역에 **예스24 상품 링크**
- 서비스에 필요한 범위에서만 저장. **전체 도서를 모아 자체 DB로 쌓지 않는다.** 가격은 짧은 주기로 갱신
  - **저장 구조**: 우리 DB에는 **책 번호(ISBN)·우리가 붙인 태그·우리가 만든 한 줄·행동 기록만** 둔다. 책소개·목차·가격·평점·표지는 **책갈피를 보여줄 때 서버가 불러와 잠깐만 캐시**한다
  - 한 줄의 재료는 가능하면 **정보나루 책소개(공공데이터)** 를 쓰고, YES24 목차는 보조로 — YES24 데이터를 가공하는 부분을 줄인다. 가공할 때도 **원래 뜻을 바꾸지 않는다** (약관 제6조: 왜곡 가공 금지)
  - 한도: 기본 등급 하루 20,000회 → 한 사람당 5회면 캐시 없이도 하루 약 4,000명. 서비스가 커지면 **Partner·Enterprise 등급을 1:1 문의로 신청** (상위 등급 유료화 예정)
- 화면에 **"예스24와 무관한 개인 프로젝트"** 를 표시한다 — 예스24 공식 서비스나 제휴로 오인되는 표시 금지 (약관 제6조·제7조)
- API 키는 **서버에서만** 사용 (웹페이지 코드에 넣지 않는다)

### 4-2. 첫인상 한 줄 만들기

| 단계 | 담당 |
|---|---|
| 책소개·목차·줄거리를 주고 "이 책에 있는 내용만으로 한 줄" 초안 | LLM |
| 규칙 검사: 길이, 금지 표현 | Python |
| 전수 검수 — 사실과 다르거나 스포일러·과장이면 고친다 | 본인 |

Olist 때와 같은 원칙이다 — **LLM은 초안, 판단은 사람, 규칙은 코드.**

**말투는 입구에 따라 섞는다** (09-29 결정, 샘플: `../data/processed/one_liners_sample.json`)

| 입구 | 말투 | 예시 | 이유 |
|---|---|---|---|
| 🎯 알고 싶은 게 있어요 | **요약형** | 평균·표본·그래프가 사람을 속이는 방법을 파헤쳐요 | 무엇을 다루는지 바로 보여야 판단할 수 있다. 가장 정확하고 검수가 쉽다 |
| 🍃 그냥 한 권 만나고 싶어요 | **질문형** | 상처는 어떤 모양으로 사람에게 남을까요? | 궁금증을 건드려 "궁금해요"와 잘 어울린다 |

상황형("~할 때")은 쓰지 않는다. 샘플 30줄 중 규칙 검사에 걸린 6줄 중 4줄이 상황형이었다 — 책 내용을 "이럴 때"로 바꿔 쓰는 말투라 재료에서 가장 멀어진다. 좋은 질문이 나오지 않는 책은 🍃에서도 요약형을 쓴다.

### 4-3. 이용자 행동 기록

익명 식별자와 이벤트만 기록한다. 개인정보는 받지 않는다.

| 이벤트 | 속성 |
|---|---|
| `visit` | 유입 경로 |
| `entry_selected` | 🎯 / 🍃 |
| `chip_selected` | 질문, 선택값 |
| `situation_written` | 적었는지 여부 (내용은 저장하지 않음) |
| `book_opened` | — |
| `first_page_edited` | 고친 항목 |
| `bookmark_shown` | 책 ID, **몇 번째 장인지**, 한 줄 말투(요약형/질문형), 화면 버전 |
| `bookmark_reacted` | 책 ID, 패스 / 궁금해요 |
| `result_viewed` | 궁금해요 개수 |
| `redraw_clicked` / `home_clicked` | 궁금해요 0개일 때 선택 |
| `book_saved` | 책 ID |
| `yes24_clicked` | 책 ID |

`화면 버전`은 2단계에서 무언가를 고쳤을 때 전후를 구분하기 위한 값이다.

### 4-4. 분석 — 1단계 모으기, 2단계 찾아서 고치기

**1단계 (~10/16): 모으고 본다**

| 볼 것 | 질문 |
|---|---|
| 퍼널 | 처음 화면 → 칩 완료 → 책 펼치기 → 첫 장 → 책갈피 1장 → 5장 완주 → 결과 → 예스24 클릭. **어디서 가장 많이 빠지나** |
| 책갈피 위치별 이탈 | **몇 번째 책갈피에서 그만두나** — 5개가 적당한가, [다시 뽑기]로 더 보는 사람은 얼마나 되나 |
| 궁금해요 | 한 사람당 몇 개 누르나, 0개인 사람은 얼마나 되나, 어떤 책·어떤 한 줄에 몰리나 |
| 입구 | 🎯와 🍃 중 어디로 많이 오나, 두 입구의 완주율·궁금해요 차이 |
| 첫 장 | 고치는 사람이 얼마나 되나 — 칩이 상황을 잘 담는가 |
| 한 줄 말투 | 요약형·질문형 카드의 궁금해요 비율 — 단, **말투가 입구에 묶여 있어 입구 차이와 섞인다.** 말투만의 효과를 보려면 2단계에서 같은 입구 안에서 나눠야 한다 |

**2단계 (10/17~): 문제 하나를 찾아서 고치고, 다시 잰다**

1단계 결과에서 **가장 큰 문제 하나**를 골라 고치고, 고치기 전과 후를 비교한다. **무엇을 고칠지는 데이터를 보고 정한다** (Kkeutjang 회고: 분석 결론 전에 기능을 정하지 않는다). 후보 예시:

| 1단계에서 이게 보이면 | 2단계에서 이렇게 고친다 |
|---|---|
| 뒤쪽 책갈피에서 많이 나간다 / 다시 뽑기를 많이 누른다 | 책갈피 개수를 조정한다 |
| 첫 장이나 책 펼치기에서 이탈이 많다 | 책 등장·첫 장 단계를 줄이거나 바꾼다 |
| 궁금해요 0개가 많다 | 칩 질문이나 태그 매칭을 바꾼다 |
| 궁금해요는 많은데 예스24 클릭이 적다 | 결과 화면에 보여주는 정보를 바꾼다 |
| (이용자가 충분히 모이면) 한 줄의 효과가 궁금하다 | 절반은 "제목 + 한 줄", 절반은 "제목만"으로 나눠 비교 |

**통계적 한계를 먼저 적는다** — 이용자 30~50명 규모에서는 작은 차이를 가려내기 어렵다. 전후 비교는 시기(유입 경로·요일)가 달라서 생기는 차이가 섞일 수 있으므로 유입 경로를 함께 기록해 나눠 본다. 결과는 **차이의 크기와 신뢰구간**으로 보고하고 "유의하다/아니다"로 단정하지 않는다.
