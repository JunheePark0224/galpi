## 1. 왜 바꾸나

- 10-02~03 친구 시험(브라우저 10개, v1): 🎯 직접 쓰기 3번이 **3번 모두** 우리 범위 밖·키워드 없음으로 막힘. 칩으로 고른 10번은 모두 찾음.
- 사용자 판단(10-04): 목적이 분명한 검색은 예스24가 더 잘한다. 갈피가 12개 주제로 그 싸움을 하면 늘 막히고, 범위를 넓힐수록 키워드 정의·검수가 끝없이 는다.
  갈피만의 것은 **고르는 재미와 우연한 만남**이다. 다만 "SQL을 배우고 싶은데 갈피를 못 잡는" 사람처럼 **방향은 있지만 책은 못 고른 사람**도 갈피의 손님이다.
- 결론: 🎯 입구(칩·직접 쓰기)를 없애고, 모든 사람이 **둘 중 하나를 고르는 질문**으로 갈피를 잡아 가게 한다.

**갈피 한 줄 정의 (v2)**: 갈피를 못 잡은 사람이 둘 중 하나를 고르는 질문에 답하며 갈피를 잡고, 원하던 책이나 운명 같은 책 한 권을 만나는 웹.
책을 읽는 사람이든 안 읽는 사람이든, 우연히 한 권을 마주쳐 읽게 되는 것이 목표다.

## 3. 질문 지도

### 3-1. 처음 두 질문 (모드·갈래) — 선택지는 여기서도 늘 둘
1. `평소 끌리는 쪽으로` vs `오늘은 낯선 쪽으로 도전`(4절). 꾹 누르기 = 평소 쪽.
2. `이야기에 빠지기` vs `뭔가 배우기`. 꾹 누르기 `갈피를 못 잡겠어요` = 둘 다 섞어서 기분 질문만 — 추천 4장은 **이야기 2 : 배우기 2**(10-05).

### 3-2. 갈래 초입 (좁힐지)
`떠오르는 게 있어요` vs `기분 따라 갈래요`. 앞쪽 → 좁히기 질문, 뒤쪽 → 기분 질문.

### 3-3. 두 종류의 질문 (선택지는 늘 둘)

| 종류 | 하는 일 | "갈피를 못 잡겠어요" |
|---|---|---|
| **좁히기** | 책 범위를 줄인다 — 배우기: 분야 → 주제 → 키워드, 이야기: 장르 묶음 → 장르 | 좁히기를 거기서 멈추고 기분 질문으로 |
| **기분** | 범위 안에서 점수를 준다 — 이야기: 온도·끌림·얻는 것·세계·분량, 배우기: 방식·분량. **바꿀 책이 없는 자리에서는 묻지 않는다**(5-2, 10-05) | 그 질문은 "상관없음"으로 두고 다음으로 |

- 선택지가 셋 이상인 곳은 두 단계로 나눈다(예: SQL / 엑셀 / 파이썬 → "DB에서 꺼내기 vs 표·코드로 분석" → "표로(엑셀) vs 코드로(파이썬)").
- 각 선택지는 **반드시 우리 태그 하나**(주제·키워드·장르·축·방식·분량)로 이어진다 — 왜 이 책인지 늘 거꾸로 따라갈 수 있다(원칙 2).
- 지도는 사람이 쓰고 고치는 문서(`docs/question-map.md`, 형식 아래)이고 앱은 그 문서에서 만든 데이터를 읽는다. 질문 문장도 사람이 정한다.

```
id: work-data-tool
종류: 좁히기
질문: 어떤 쪽이 더 끌려요?
A: "DB에서 꺼내기"  → 키워드 SQL            (끝)
B: "표·코드로 분석" → 다음 질문 work-data-sheet
```

**예시 길 (SQL)**: 평소 끌리는 쪽으로 → 뭔가 배우기 → 떠오르는 게 있어요 → 일을 더 잘하기 → 숫자·도구 다루기 → 데이터 읽고 분석 → 데이터 꺼내는 도구 → DB에서 꺼내기(SQL) → 실제로 써먹는 쪽(방식 실습·사례 — SQL 책엔 사례 책이 없어 "따라 하기 / 사례" 질문은 넘어감, 5-2) → 가볍게 읽히는 얇은 책(분량 얇음) → 다섯 장.

### 3-4. 키워드 정의
지도의 좁히기 끝은 키워드·장르다. **정의가 없는 키워드 19개**(SQL, 기초 통계, 확률, 회귀분석, 가설검정, 챗GPT, 클로드, 제미나이, 프롬프트 엔지니어링, 바이브 코딩, AI 에이전트, 이미지·영상 생성, 파이썬 자동화, 코파일럿·M365, AI 업무 활용, 습관, 집중력, 뇌과학, 일하는 법)는 지도 작업과 함께 정의를 쓴다(`target-chips.md` "새 키워드 정의").

## 4. 도전 루트

- 사용자 경험(니코마코스 윤리학 — 이과생의 철학책 도전): 사람은 관심 분야 밖의 책을 잘 마주치지 않는다. 갈피가 그 문을 열어 준다.
- **"무엇"(분야·장르)만 뒤집고 "어떻게"(분량·방식·온도)는 그 사람 답을 지킨다** — 멀지만 들어갈 만한 책.
  - **10-05**: 배우기 → 이야기로 건너가면(먼 곳 표의 배우기 규칙은 모두 이야기 장르) 이야기 책엔 방식 태그가 없어 방식 답이 사라지고 있었다(점검: 개념 vs 실습 결과 100% 같음). 그래서 방식 답을 이야기 축 하나로 옮긴다 — **개념 → 알게 됨, 실습 → 현실, 사례 → 몰입**(`balance-game.md` 10-05 갱신). 분량은 원래 두 갈래가 같은 쪽수 기준.
  - **10-05**: 갈래에서 "못 잡겠어요"(섞어서) + 도전 → 뒤집을 갈래가 없으므로 **이야기·배우기 중 한 갈래를 무작위로**(뽑기 시드로 정해 같은 시드면 같은 갈래). 전에는 평소와 결과가 같았다.
- 흐름: 첫 질문에서 `오늘은 낯선 쪽으로 도전` → 평소처럼 취향대로 답함 → 갈피가 그 답의 **먼 곳**에서, 분량·방식·온도는 답에 맞춰 고름 → 책갈피는 **도전 모양**(시안으로 정함), 첫 장 "평소의 당신과 반대편에서 골랐어요".
- **먼 곳 표**: 갈래마다 먼 갈래를 사람이 정해 문서로 공개(`docs/question-map.md` 안). 예: 데이터·AI ↔ 인문·시·예술 / SF ↔ 에세이·시 / 마음 돌보기 ↔ 과학 교양.

## 5. 뽑기 규칙 (순수 함수 · 테스트 100%)

1. **범위**: 좁히기 답이 가리키는 태그의 책. 첫 질문부터 "못 잡겠어요"면 전체. 도전이면 먼 곳 표로 바꾼 범위.
2. **점수**: 범위 안 책마다 기분 답과 맞는 만큼(이야기 축은 지금 `balance-game.md` 점수 규칙, 배우기는 방식·분량). 넘긴 질문은 0. 분량은 두 갈래 모두 **얇음 ≤ 280쪽, 두꺼움 ≥ 380쪽** 하나(10-05). "실제로 써먹는 쪽"은 실습·사례 둘 다 +2, 다음 질문에서 하나를 고르면 그것만.
   - **바꿀 책이 없으면 묻지 않는다 (10-05)**: 기분 질문은 그 자리에서 뽑기가 고를 수 있는 책(넓혀야 하면 넓힌 단계에서, 좁은 단계 책이 먼저 다 들어가고 남은 자리를 다투는 책) 가운데 **두 답이 각각 1권 이상 점수 > 0을 줄 때만** 묻는다. 다투는 책이 남은 자리보다 많지 않으면(무엇을 골라도 같은 책) 넘긴다. 넘긴 질문은 "못 잡겠어요"와 같은 0점이지만 **화면에 나오지 않고**, 답(E-32)·되돌리기 대상·S-04 기분·깊이·모르겠어요 수에 들어가지 않는다. 책 전체로 판정(이번 방문에서 본 책은 따지지 않음)하고, 도전이면 먼 곳의 책으로 판정. 판정 결과는 `web/src/data/mood-skips.json` — 브라우저와 서버가 같은 표로 길을 걸어 같은 질문을 묻는다(`npm run books:import`·`map:build`가 다시 만들고, 데이터 테스트가 책과 표가 맞는지 확인).
3. **추천 4장**: 점수 높은 순, 같으면 무작위. **같은 저자 한 판에 1권**(10-05 구현 — 저자 줄의 이름 중 하나라도 같으면 같은 저자, 운명 1장 포함. 범위의 저자가 4명이 안 되면 5-5처럼 넓힌다). 넓은 범위면 장르를 섞음(한 판 장르 3.5개 이상 유지). 이번 방문에서 본 책은 뺌. **섞어서(갈래 못 잡겠어요)는 이야기 2 : 배우기 2**(10-05 — 전엔 책 수 비율 때문에 75~83%가 배우기).
4. **운명 1장**: 마지막으로 좁힌 범위의 **바로 윗단계**에서 무작위 1권(추천과 겹치지 않게, 넓혔으면 넓힌 단계에서). **고른 갈래 밖으로는 나가지 않는다**(10-05 — 이야기 길이면 이야기 책, 배우기 길이면 배우기 책. 갈래까지만 좁혔으면 그 갈래 전체에서. 전엔 장르 없이 간 이야기 길의 78%가 배우기 책). 섞어서면 전체(어느 갈래든). 다섯 장 중 자리도 무작위. 화면엔 표시 없음, 기록은 `pick_type: random`.
5. **모자랄 때**: 추천 4장이 안 차면(저자 4명이 안 되면) **한 단계씩** 윗단계로 넓혀 채운다 — 좁혀 온 길을 거꾸로 하나씩(키워드 → 그 위 키워드 묶음 → 주제 → …, 예: 역사 0권 → 역사·사회 0권 → 인문·역사·사회 10권에서 멈춤), **갈래 전체 위로는 넘지 않는다**(10-05 — 전엔 바로 윗단계도 모자라면 갈래 전체로 뛰어 "역사"가 이야기 100권 아무 책이 됐다). 좁힌 단계의 책이 늘 먼저(LEVEL_LEAD). 0권 장르·키워드도 선택지는 그대로 둔다(10-04 "모든 장르가 있다고 본다"). 10절: 첫 장에 책 수 안내는 하지 않음.
6. **시뮬레이션**: 지도의 모든 길 끝마다 책 수·채움률을 `simulate_draws.py`(확장)로 재고, 4권 미만인 길을 표로. 웹 뽑기와 같은 분포여야 한다(지금 규칙 그대로). — 10-05 확인: `simulate_draws.py`는 아직 v1(합성 책, 칩·수준 점수)만 모델링한다. 길 끝 책 수는 `npm run map:coverage`가 잰다. 🍃 기본 뽑기(점수·τ·Δ·장르 상한)는 `parity.test.ts`로 같음을 지킨다.
7. **매일 책 작업**: 키워드·주제 칸 대신 **책이 모자란 길 끝**을 채운다(`src/pipeline/gaps.py`).

## 6. 기록·분석 (taxonomy v1.0)

- **없앰**: 🎯 입력 관련(칩 고르기, 목표 제출, 직접 쓴 목표, 목표 범위 확인, 첫 장 고치기 E-xx는 v1.0에서 번호와 함께 정리).
- **바꿈**: 밸런스 답(E-24) → **질문 답**: `node_id`, `kind`(narrow·mood), `choice`(A·B·unsure), `depth`, `position`, `elapsed_ms`. 꾹 누르다 뗌(E-25)에 `node_id`.
- **새로**: **이전 질문으로**(`node_id`, `depth`) · **길 완성**(최종 범위 id, 깊이, 모르겠어요 횟수, `mode`: normal·challenge). 공통 `entry`는 `mode`·첫 갈래로 바뀐다.
- **유지**: 책갈피 이후 이벤트 전부, `pick_type`(추천·운명).
- **분석 질문**: ① 어디까지 좁히나 — 질문별 모르겠어요·되돌리기 비율로 헷갈리는 질문 찾기 ② 좁힐수록 궁금해요가 느나 ③ 추천 4장 vs 운명 1장 ④ 도전 루트의 궁금해요·꽂기 vs 일반 ⑤ 책이 모자란 길. 결과는 차이의 크기 + 신뢰구간(원칙 5).
- **처리방침**: 직접 쓴 글을 받지 않고 Anthropic 전달도 없어진다 — 처리방침부터 고친다. 이벤트 원칙 3-1(md → csv → schema.ts → 테스트 → track())을 지킨다.

일정(배포 10/16·분석 10/31)은 잠정 — 순서만 지킨다. 가장 오래 걸리는 것은 2(사람이 정하는 질문 문장).

## 8. 시안으로 정할 것 (구현 전, 시각 비교)
- S-01 홈 한 입구 · S-02 갈림길(지나온 길 표시, 이전 질문, 첫 질문 "평소 / 도전") · 도전 책갈피 모양 · S-04 "당신이 고른 길" 요약.

## 9. 위험과 대응
- **질문이 많아 지침**: 갈래 초입에서 기분 따라 가면 3~5개로 끝남, 매 단계 "못 잡겠어요"로 멈춤. 질문별 모르겠어요·되돌리기 비율로 지루한 질문을 찾아 고친다.
- **길 끝에 책이 없음**: 윗단계로 채우고 솔직히 말함(5절-5), 모자란 길을 매일 채움(5절-7).
- **v1 데이터와 비교**: 이벤트가 크게 바뀌므로 v1 기준점은 책갈피 이후 이벤트(공통)로만 비교한다.
- **🎯 책 276권**: 버리지 않음 — "배우기" 갈래의 재료.

## 10. 시안 결정 (10-04, 사용자)
- **S-02 질문 화면**: 지금 밸런스 게임 화면 그대로(책갈피 모양 카드 둘 + vs + 꾹 눌러 "갈피를 못 잡겠어요") + 왼쪽 위 [← 이전 질문]. **질문하는 동안 지나온 길·몇 번째 질문은 보여 주지 않는다**(MBTI처럼 끝나고 보여 줌 — 운명적으로 만나는 맛). 지금의 "n / 9" 막대는 없앤다.
- **S-01 홈**: 입구 버튼 하나 [갈피 잡으러 가기] + 아래 한 줄 "질문 몇 개면 한 권을 만나요". 서재 권수·우체통은 그대로.
- **S-04 첫 장**: "당신이 고른 길"(지나온 길 + 기분)을 여기서 처음 보여 준다. 넘긴 기분 질문(5-2)은 기분에 나오지 않는다(10-05). "실제로 써먹는 쪽" 다음에 "바로 따라 해 보기"를 고르면 뒤의 것만, 다음 질문을 넘기거나 못 잡겠어요면 "실제로 써먹는 쪽"이 나온다. **책 수 안내("…아직 2권이라 …로 채웠어요")는 넣지 않는다** — 모자라면 조용히 넓혀 채우고, 책을 많이 넣어 모자람을 없앤다. 도전이면 한 줄 "평소의 당신과 반대편에서 골랐어요".
- **도전 책갈피는 따로 꾸미지 않는다** — 평소와 같은 모양(책갈피 색·동물은 나중에 전체적으로 다양하게 늘릴 계획). 8절의 "도전 책갈피 모양"은 취소.
