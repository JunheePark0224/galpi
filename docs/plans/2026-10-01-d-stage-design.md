# D 단계 설계 — 주제 넓히기 + 매일 책 자동 추가 (2026-10-01)

**근거(사용자 결정, 10-01 대화)**: P4 배포 뒤 **D 단계를 P5보다 먼저**. 최종 목표는 "검수 없이 매일 책이 저장되는 것". 운영 전에 칸이 너무 적으므로 **중간 크기로 넓힌다**(🎯 6 → 12, 🍃 9 → 12, 추천안 그대로 — `docs/expansion-candidates.md`). 🎯 입력은 **B안**(큰 직접 쓰기 칸 + 예시 칩 6개). 키워드 구조는 2단(주제 = 후보 범위, 키워드 = 같은 주제 안에서 +3점). 결정 기록: `context.md` 10-01 행들.

## 0. 범위와 순서

하나의 큰 작업이 아니라 **다섯 묶음**이다. 묶음마다 구현 계획(`docs/plans/`)을 따로 쓴다.

| 묶음 | 무엇 | 먼저 필요한 것 | 사람 |
|---|---|---|---|
| **D-A 분류 넓히기** | 새 주제 6·장르 3·키워드를 문서와 앱(목록·분류·이벤트 값)에 넣는다. 아직 책은 0권이어도 앱이 깨지지 않게 | — | 키워드 초안 승인(10-01 완료) |
| **D-B 파이프라인(D-07)** | GitHub Actions로 매일: 빈 곳 계산 → 후보 → AI 태그 → 규칙 검사 → PR. 검수 페이지·일치율 기록 | D-A | GitHub Secrets 2개 |
| **D-C 처음 채우기** | 파이프라인을 하루 50권으로 돌려 약 600권까지. 이 기간이 곧 시험 운행(검수) | D-B | 검수 |
| **D-D 🎯 입력 B안** | S-02: 직접 쓰기 칸 + 예시 칩 6개. 이벤트 정의 먼저 | D-A (주제 목록) | 시안 고르기 |
| **D-E 갈피의 서재 숫자(F-23)** | 처음 화면 "갈피의 서재 N권 · 오늘 +M권" | D-C 끝 | 시안 고르기 |

순서: **D-A → D-B → (D-C 진행 중에 D-D) → D-E**. D-D는 D-A만 끝나면 따로 진행할 수 있다.

## 1. D-A 분류 넓히기

### 1-1. 목록

| 분야(새) | 🎯 주제 | 세부 키워드 초안 (책을 모은 뒤 5권 이상·60% 이하 규칙으로 확정) |
|---|---|---|
| 돈·경제 | 돈 관리·투자 | 재테크 기초 · 주식 · ETF·펀드 · 부동산·청약 · 연금·노후 · 돈의 심리 |
| 돈·경제 | 경제 상식 | 금리·환율 · 경제 뉴스 읽기 · 행동경제학 · 경제사·자본주의 · 트렌드 |
| 마음·관계 | 마음 돌보기 | 불안·걱정 · 자존감 · 감정 다루기 · 번아웃·스트레스 · 우울 · 명상·마음챙김 |
| 마음·관계 | 대화·관계 | 말투·대화법 · 발표 · 설득·협상 · 거리 두기 · 갈등·무례 대처 · 호감·사회생활 |
| 일·커리어 | 취업·커리어 | 자소서·면접 · 이직·퇴사 · 커리어 설계 · 퍼스널 브랜딩 · 직장 생활 |
| 일·커리어 | 글쓰기 | 에세이·책 쓰기 · 업무 글 · 문해력·어휘 · 카피라이팅 · 일기·편지 |

- 기존 습관·집중의 "마음·회복"은 **마음 돌보기의 "번아웃·스트레스"·"불안·걱정"으로 옮긴다**(지금 5권은 D-C 검수 때 새 주제로 다시 태그). 습관·집중 = 습관 · 집중력 · 뇌과학
- 🍃 새 장르: **역사 · 사회·시사 · 호러·괴담**. 경계 한 줄씩(`expansion-candidates.md` 6절)을 `book-pool.md`에: 호러 = 초자연·괴이가 중심 / 추리 = 범인·사건 풀이가 중심, 사회·시사 = 지금 사회의 문제 / 인문 = 생각·철학, 역사 = 지난 일이 중심
- 🍃 권수: "딴 세상" 25%를 맞추려 SF·판타지·호러를 늘린다. 장르별 목표 권수는 `book-pool.md` 1절 표를 다시 쓴다(첫 채우기 목표 🍃 약 300 + 🎯 약 300)

### 1-2. 앱에 묶여 있는 곳 (코드)

`web/src/lib/books/taxonomy.ts`(FIELD_OF_TOPIC·TOPIC_CHIPS·TOPICS·LEAF_GENRES), `web/src/data/vocab.json`(키워드 → 단어 패턴), `normalize.ts`·`request.ts`·`draw.ts`(목록 검사), `lib/goal/classify.ts`(Claude 목록·enum), `lib/goal/match.ts`, `lib/flow/*`, `TargetInput.tsx`(지금 칩 6개 — D-D 전까지는 **기존 6개 칩을 그대로** 두고 새 주제는 직접 쓰기로만 닿는다), `lib/track/props.ts`·`schema.ts`(이벤트의 topic·genre 값 목록이 있으면 taxonomy 먼저).

- **책이 적은 주제는 아직 켜지 않는다(10-01 결정)**: 🎯 주제는 books.json에 **10권 이상**일 때만 "활성" — 직접 쓰기 분류(Claude 목록·enum, 단어 매칭)와 보기 칩의 대상이 된다. 활성 전에 "주식"이라고 쓰면 지금처럼 가장 가까운 활성 주제 + `matched=false`(못 찾은 요청으로 기록). 파이프라인이 10권을 넘기면 다음 배포부터 자동으로 켜진다. 새 안내 문구도, 엉뚱한 주제로 넘기는 규칙도 필요 없다. 🍃 장르는 점수로 전체에서 뽑으므로 0권이어도 그냥 안 나올 뿐 — 활성 규칙 없음
- 분류 정확도: 새 주제가 들어간 지시문으로 `goal:grade`(30개)와 처음 보는 글 세트를 **새 주제 예시를 더해** 다시 잰다. temperature 0
- taxonomy: topic 값 목록이 이벤트 속성 정의에 있으면 md → csv → schema → 테스트를 한 커밋에서

## 2. D-B 파이프라인 (D-07)

### 2-1. 모양

```
GitHub Actions (매일 06:00 KST + 손으로 실행)
  └ python -m src.pipeline.run_daily
       gaps      books.json → 오늘 채울 칸과 권수 (키워드 < 5 → 주제 < 목표 → 🍃 장르·축 부족 순)
       candidates 예스24 목록·검색 → D1 규칙(일반 도서·소개·목차·평점, 한 저자 2권, 이미 있는 책·다른 판 제외)
       tagger    Anthropic API → 우리 태그 + 한 줄 + 짧은 근거 + 확신도 (구조화 출력, enum = 우리 목록)
       checks    한 줄 규칙(check_one_liners)·스키마·축 쏠림·근거가 책소개를 베끼지 않았나 → 걸리면 대기 목록
       merge     web/src/data/books.json에 추가 + data/additions/YYYY-MM-DD.json(우리 태그·근거·확신도만)
       simulate  simulate_real 기준(🍃 첫 뽑기 채움 95%+, 장르 3.5+) — 떨어지면 PR에 경고
  └ PR "오늘의 새 책 YYYY-MM-DD" (config.auto_merge = false: 사람 검수 / true: 검사 통과 시 자동 병합 → Vercel 배포)
```

- 코드: `src/pipeline/` 패키지(작은 파일 여럿 — gaps·candidates·tagger·checks·merge·review·agreement·run_daily). 기존 `collect_candidates.py`·`check_one_liners.py`·`simulate_real.py`의 함수를 가져다 쓴다(복사 금지)
- 설정: `data/pipeline/config.json` — `daily_count`(처음 50, 운영 30), `auto_merge`(false), `sample_rate`(0.1), `model`
- 키: GitHub Secrets `YES24_API_KEY`·`ANTHROPIC_API_KEY`(galpi 워크스페이스, 월 $5). 출력·로그에 값 없음
- **YES24 약관**: 책소개·목차는 태그를 붙이는 **입력으로만** 쓰고 저장소·PR·Actions 기록에 남기지 않는다. 근거는 "자기 말 30자 이내", 책소개와 겹치는 표현이 많으면 버린다. 저장하는 것은 ISBN·제목·저자·쪽수·우리 태그·우리 한 줄·우리 근거
- 실패: 예스24·Anthropic이 실패하면 그날은 PR 없이 끝나고 Actions 기록에 이유만. 하루치가 반만 되면 된 만큼만 PR

### 2-2. 태그 모델·지시문 — 먼저 200권으로 재기

1. 태거를 **이미 검수한 200권**(입력: 로컬 예스24 캐시, 정답: `books_v1.json`)에 돌려 항목별 일치율을 잰다 — 주제·키워드·방식·축 4개·한 줄(그대로 쓸 만한가)
2. Haiku 4.5와 Sonnet 5.5를 비교(비용·일치율), 지시문은 `balance-game.md` 태그 기준표 + `target-chips.md` 정의 그대로. 축 "세계"는 09-30 규칙
3. 이 숫자가 시험 운행의 출발점. 처음 재는 200권은 지시문을 고친 세트가 되므로, 고친 뒤에는 **D-C의 새 책**으로만 졸업을 판단한다(표본 안 수치로 졸업하지 않는다 — 원칙 4)

### 2-3. 검수와 졸업

- **검수**: `python -m src.pipeline.review YYYY-MM-DD` → 로컬 검수 페이지(D4와 같은 모양, 예스24 글은 내 컴퓨터에서 불러옴) → 고친 답을 내려받기 → `--apply`로 PR 브랜치의 books.json을 고치고 `data/pipeline/agreement.csv`에 그날 항목별 일치율 한 줄
- **일치율**: 항목별로 "사람이 고치지 않은 비율". 키워드는 집합이 같으면 일치
- **졸업**: 연속 3회 검수에서 **모든 항목 95% 이상** → 사용자에게 알리고, 승인받아 `auto_merge: true`
- **졸업 뒤**: 주 1회 지난 7일 추가분의 10%를 뽑아 검수(Actions가 목록을 이슈로). 어느 항목이든 90% 아래로 떨어지면 `auto_merge`를 다시 끄자고 제안

### 2-4. 원칙 2 고치기

CLAUDE.md 원칙 2와 PRD: "추천 기준은 사람이 정하고 설명할 수 있어야 한다 — **태그 기준표는 사람이 정하고, AI가 그 기준표대로 붙이며, 일치율과 표본 검수로 확인한다**". D-B 구현 계획의 첫 커밋.

## 3. D-C 처음 채우기

- 하루 50권, 칸 목표: 🎯 주제마다 25권 이상·키워드마다 5권 이상, 🍃 장르마다 25권 이상 + 축마다 양쪽 25% 이상 → 약 600권
- 이 기간이 시험 운행. 졸업하면 남은 칸은 검수 없이
- 끝나면: 키워드 확정(5권·60%), `simulate_real` 재실행, 분류 30개 재채점

## 4. D-D 🎯 입력 B안 (간단히 — 자기 구현 계획에서 자세히)

- 큰 직접 쓰기 칸 + 예시 칩 6개(첫 버전 `돈 관리` `취업 준비` `불안할 때` `데이터 분석` `AI 잘 쓰기` `글 잘 쓰기`). 칩을 누르면 칸에 그 말이 채워지고 분류로 간다(칩 → 주제는 미리 정해 둬서 AI 호출 없이)
- 이벤트: 지금 `chip_selected`·`goal_submitted.is_free_text`의 뜻이 바뀐다 → taxonomy 먼저(예: 예시 칩에서 시작했는지 속성 하나)
- 화면은 시안 2~3개 비교로

## 5. D-E 갈피의 서재 숫자 (F-23)

D-C가 끝난 뒤. 숫자 = books.json 권수, 오늘 +M = 그날 `data/additions/` 권수(빌드 때 계산). 시안 비교.
