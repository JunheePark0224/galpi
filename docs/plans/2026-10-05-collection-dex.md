## 도감 (사용자 결정)

- **위치: 내 책갈피 안** — 맨 위 [막대 | 도감] 전환 (시안 ①). 로그인 전에는 내 책갈피 대신 도감 칸이 모두 실루엣 + "로그인하면 만난 책갈피가 도감에 모여요" + [로그인하고 모으기] (시안 ②). 머리글 메뉴는 늘리지 않는다.
- **기준: 나온 책갈피** — 책장(S-05)에서 그 책갈피가 보인 순간 기록 (꽂지 않아도). **로그인한 사람만** 기록.
  서버가 그림을 다시 계산해 기록한다 (브라우저가 보낸 그림을 믿지 않는다 — 전설을 꾸며 넣지 못하게).
- 화면: 모은 수 "동물 n / 16 · 배경 n / 11 · 소품 n / 16"(→ 10-05 수정: 소품 15, 설계 8절), [동물 | 배경 | 소품] 탭, 칸 제목 **일반판 · 한정판 · 초판본**(초판본은 금빛 글씨),
  만난 칸 = 처음 만난 그 그림, **못 만난 칸 = 실루엣 + "???"**(초판본도 실루엣), 새로 만난 칸 NEW(도감을 한 번 보면 사라짐),
  맨 아래 확률 공개 "책과는 상관없이 뽑혀요. 돈으로 뽑는 기능은 없어요."
- **처음 만날 때 (시안 ③, 사용자: 너무 튀지 않게, 조금 뒤 사라지게)**: 책갈피 위 작은 배지 "처음 만난 동물!" / "처음 만난 배경!" / "처음 만난 소품!"
  (여럿이면 한 줄로 합침, 등급이 높으면 앞에 등급 — "초판본 · 처음 만난 동물!" → 10-05 수정: 부분 이름마다, 설계 8절), 약 2.5초 뒤 스르르 사라짐. 일반판은 더 작고 조용하게.
  로그인한 사람만 (로그인 전에는 "처음"을 알 수 없으므로 배지 없음).

## 설계 (구현) — 10-05, `feat/collection-dex`

### 1. 등급 뽑기 (`web/src/lib/art/combine.ts`)
- 목록은 등급별 상수(`KIND_TIERS`) 하나에서: 동물 7/5/4, 배경 6/3/2, 하늘 소품 5/2/1, 땅 소품 5/2/1("없음"은 일반판). 도감의 이름은 `lib/art/names.ts`.
- `artsForDraw(count, seed)`: mulberry32(seed) 하나로 책갈피마다 동물 → 배경 → 하늘 → 땅 순서로 **각각** `tierFor(rng())`(0.01 미만 초판본, 0.10 미만 한정판, 나머지 일반판) → 그 등급 안에서 고르게. 일반판 동물은 한 판 안에서 겹치지 않게(판 처음에 일반판 7종을 섞어 두고 차례로 — 다 쓰면 고르게). 같은 seed = 같은 그림.
- 단위 테스트: seed 2만 번에서 네 부분 모두 90/9/1 ±1%p, 모든 값이 나옴, 재현성, 일반판 동물 안 겹침.
- **`rare`는 남긴다**: 넷 중 하나라도 한정판 이상이면 true(옛 기록은 모두 false — 그대로 맞음). 부분별 등급은 **값으로 찾는다**(`tierOf(kind, value)`, `artTier`) — 저장 데이터·이벤트 모양 변경 없음. `parseArt`는 새 값을 받고 `rare`를 부분에서 다시 계산한다(브라우저가 보낸 `rare`는 믿지 않음, 옛 그림은 그대로 통과).

### 2. 서버가 믿는 만남
- `/api/books/draw` 응답에 `art: { seed, count, sig }` — seed는 **늘 서버의 무작위 32비트**(요청의 `seed`는 책만 재현, 그림은 아님), `sig` = HMAC-SHA256(`galpi-art:v1:{seed}:{count}`, `COLLECTION_SIGNING_SECRET`) base64url. 브라우저는 이 seed로 그림을 그린다(`toDrawView`).
- 비밀값: 서버 전용 `COLLECTION_SIGNING_SECRET`(`.env.example` 빈 칸, `deploy.md` 3절 — **사용자가 Vercel Production에**). 없을 때 `NODE_ENV !== "production"`이면 이름부터 가짜인 개발용 값, **운영에서는 서명 없음(`sig: null`) → 기록 꺼짐**, 그림·사이트는 그대로.
- S-05에서 책갈피가 보일 때(E-07과 같은 손잡이 — `Flow.tsx` `meet`) 로그인 상태면 `POST /api/collection/found { seed, count, sig, index }`. 서버 순서: 같은 사이트·속도 제한(분당 60, 라이브러리와 같음)·300바이트 → 모양 검사(400) → 비밀값 없음(503) → **서명 확인(403, 상수 시간 비교)** → 로그인(401) → 쓰기 키 없음(503) → `artsForDraw(count, seed)[index]`를 **서버가 다시 계산** → 네 부분 기록 → 새로 기록된 것만 `{ found: [{kind, value, tier}] }`. 서명이 로그인보다 먼저라 위조는 로그인과 무관하게 거절된다(E2E가 진짜 서버로 확인).
- 같은 책갈피를 다시 보내도 처음 만난 때·그림은 바뀌지 않고 `found: []`. 서명된 뽑기를 여러 번 받아 좋은 것만 보고하는 것은 "많이 뽑기"와 같아 막지 않는다(뽑기 자체가 분당 60).
- 로그인 전: 요청도 배지도 없음. 꽂기(`saves.art`)는 그대로 브라우저의 그림을 `parseArt`로 검사해 저장 — 내 책갈피 그림은 꾸며도 자기 화면만 바뀌고 도감에는 들어가지 않는다.

### 3. 데이터 (`web/supabase/migrations/0004_collection.sql`)
- `collection(user_id, kind, value, first_met_at, first_art jsonb, is_new)`, 기본키 `(user_id, kind, value)`, kind 4종 check, value 영문 1~24자 check, `first_art` 2000바이트 미만, 계정 삭제 시 함께 삭제.
- RLS: authenticated는 **자기 줄 select만**. insert·update·delete 권한 없음 — 쓰기는 서버 라우트가 세션으로 사용자를 확인한 뒤 **service role**(`SUPABASE_SERVICE_ROLE_KEY`)로, 늘 그 사용자 id로만. (계획의 "라이브러리처럼 세션으로 쓰기"에서 바꿈 — 세션에 insert를 주면 anon 키로 전설을 직접 넣을 수 있어 "꾸며 넣지 못하게"가 깨진다.) 확인 스크립트 `web/supabase/checks/collection_rls.sql`.
- 저장소 패턴: `CollectionStore`(`items`·`record`·`markSeen`), Supabase 구현 `lib/collection/supabaseStore.ts`, 테스트용 `__fixtures__/memoryStore.ts`. `record`는 insert … on conflict do nothing returning — 새 줄만 돌아온다.
- 표가 없으면(`42P01`·`PGRST205`) 라우트가 503 → 도감은 "도감을 불러오지 못했어요." + [다시 불러오기], 배지 없음, 사이트는 그대로. NEW는 `is_new`, 도감을 연 뒤 `POST /api/collection/seen`이 지움(그 화면에서는 보이고 다음부터 사라짐).

### 4. 이벤트 (taxonomy v1.3, 처리방침 먼저 — 갱신일 2026-10-05)

- E-36 `collection_item_found`(system): 서버가 새로 기록한 부분마다, 응답을 받은 뒤 브라우저가 `track()`. 속성 `part_kind`("animal"/"bg"/"sky"/"ground")·`part_value`·`tier`("common"/"limited"/"first_edition"). 새 동사 `found`, 새 분류 `도감`.

### 7. 보안 리뷰 반영 (10-05)
- 표 v2: 서명 글 `galpi-art:v2:{seed}:{count}:{iat}:{sub}` — `iat`(발급 초) + `sub`(뽑을 때 로그인한 사람, 아니면 빈 칸). found는 **2시간** 지난 표(또는 5분 넘게 미래)를 403, 표에 `sub`가 있는데 세션 사람과 다르면 403. 로그인 전에 받은 표(`sub` 없음)는 2시간 안에서만 받는다. v1 표는 받지 않는다(모양에 `iat`가 없으면 400, 있어도 서명이 맞지 않아 403). → seed를 모아 "도감 키트"로 나눠 줄 수 없다.
- 뽑기의 사람 확인은 `sb-…-auth-token` 쿠키가 있을 때만(`/api/track`과 같은 `verifiedUserId`) — 로그인 전 뽑기는 네트워크 호출 없음. 로그인한 뽑기는 `getClaims` 한 번: 지금 프로젝트 JWT가 대칭 키라 Supabase Auth 왕복 1번(로그인한 사람의 이벤트마다 `/api/track`이 이미 하는 것과 같음, 비대칭 키로 바꾸면 로컬 검증). 실제 지연은 실 Supabase 세션이 없어 재지 못함. 실패하면 `sub` 없이 발급(뽑기는 그대로).
- 운영에서 `COLLECTION_SIGNING_SECRET`이 32자 미만이면 없는 것과 같이 기록을 끄고 로그에 한 줄(값은 쓰지 않음).
- 처리방침: 도감은 1년 자동 삭제가 아니라 탈퇴 때까지 — "내 책갈피, 도감과 로그인 정보는 탈퇴를 요청할 때까지 보관해요", 탈퇴 문장에 도감, 새 행은 "책을 넘기며 만난".
- SVG id: `BookmarkArt`가 `clipId` 뒤에 `useId()`를 붙인다(같은 책이 막대·시트·끄는 사본에 동시에 그려져도 겹치지 않음).
- 효과 비용: SVG 안 애니메이션은 매 프레임 다시 그린다 — 전체 효과는 내려앉은 S-05 책갈피 하나만, 나머지는 `fx="light"`.
