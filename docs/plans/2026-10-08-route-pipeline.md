# 파이프라인: "이 칸에 맞나?" → "어느 칸인가?" (10-08, 사용자: 정교하게, 비용은 최대한 아껴서)

## 왜
지금은 칸(🍃 장르 / 🎯 주제)을 정해 검색하고, AI에게 "이 칸에 맞나?"만 묻는다. 맞지 않으면 다른 칸을 알려 줘도 **버린다**.
- 10-07 실행 539권: 들어감 276(51%) · **버림 133(25%)** · 검수 98(18%) · 보류 32(6%)
- 버린 133권 중 125권은 우리 29개 장르 안의 다른 장르를 제안, **115권은 두 AI가 같은 장르를 제안**. 정말 갈 곳이 없던 건 8권(희곡 등)
- 지금까지 버린 책 189권(중복 제외): 같은 칸 제안 115 · 한쪽만/다름 12 · 제안 없음 58(10-01~05 실행분 52 — 그때는 제안을 묻지 않음)
→ 장르가 모자란 게 아니라 **구조가 버리고 있다**.

## 무엇을 바꾸나
1. **칸 고르기** — 태깅 지시문과 답 형식(schema)에서 `fits`/`suggest`를 `slot`으로: 같은 갈래(🍃면 29개 장르, 🎯면 16개 주제) 안에서 이 책이 들어갈 칸 하나, 어디에도 없으면 `""`. 검색한 칸은 힌트로만 준다("이 칸으로 찾았다"). 기준은 지금 정의서 그대로 — 정의서는 이미 모든 칸의 기준과 경계 표를 담고 있고 캐시되는 시스템 지시문이라 지시문이 길어지지 않는다.
   - pass A는 고른 칸의 기준으로 태그·한 줄을 붙인다. pass B는 지금처럼 보지 않고 따로 칸과 태그를 고른다.
2. **결정**
   - 두 패스가 같은 칸 → 그 칸으로, 나머지 태그 비교는 지금 규칙 그대로(일치 → 들어감, 갈림 → 아래 3)
   - 칸이 갈림 → **세 번째 패스(tiebreak.py, 10-06 서재 재태깅에서 검증: 칸 3/3)** 로 3표 중 2표인 칸. 셋 다 다르면 사람
   - 두 패스 모두 `""` → 버림(진짜로 우리 칸 밖 — 희곡 등). 한쪽만 `""` → 세 번째 패스
   - 갈래를 넘는 이동(🍃 ↔ 🎯)은 지금처럼 검수 페이지의 [다른 갈래로]로 사람이(이번 범위 밖)
3. **태그가 갈릴 때** — 지금 사람에게 가는 갈림(온도·끌림·세계 등 🍃 축, 방식) 중 **세 번째 패스가 2/3로 정할 수 있는 칸**(10-06 금 세트 검증: 축 6/6, 방식 2/2)은 세 번째 패스로. 키워드(5/10)와 한 줄 문제는 계속 사람. → 사람 검수가 줄어든다(지난번 "A안").

## 비용을 아끼는 방법 (정교함은 그대로)
| 방법 | 효과 | 정교함 |
|---|---|---|
| **Message Batches API** — 하루 실행분을 한 번에 맡기고 결과를 받음(보통 1시간 안, 최대 24시간) | 호출값 **50% 할인** | 같은 모델·같은 지시문 — 그대로 |
| 정의서 시스템 지시문 캐시(이미 함) — 모든 책이 같은 앞부분을 씀 | 입력값 대부분 캐시 가격 | 그대로 |
| 세 번째 패스는 **갈린 책만** | 전체가 아니라 갈린 책(약 20~30%)에만 1회 더 | 사람 대신 2/3 — 금 세트에서 검증된 칸만 |
| **버린 189권부터** 새 방식으로 | 새 후보보다 들어올 확률이 높음(115권은 두 AI가 같은 칸을 이미 지목) | — |
| 모델은 두 패스 모두 Sonnet 5.5 유지 | — | Haiku로 낮추지 않음(10-01 비교에서 Sonnet이 나음) |

예상: 지금 권당 약 $0.028(Sonnet 두 번) → 배치로 약 **$0.014**, 세 번째 패스 포함 평균 약 $0.017. 버린 189권 다시 돌리기 ≈ $3.5.

## 순서 (각 단계에 테스트 먼저)
1. **지시문·답 형식** — `prompt.py` 칸 고르기, `schema` `slot` enum(갈래 안의 칸 + ""), `checks.decide`·`agreement`·`merge`가 `slot`을 읽게. 정의서 문구는 그대로(지시문만) — `rules_version` v3.3, `label-dictionary.md` 변경 기록 한 줄.
2. **세 번째 패스를 매일 실행에** — `tiebreak.py`를 `run_daily`에 연결(칸 갈림 + 2/3로 정할 수 있는 태그 갈림만). 지금 서재 재태깅용 코드 재사용.
3. **배치 API** — `tagger.py`에 배치 제출·결과 받기(같은 요청 본문, `custom_id` = isbn+패스). 실행은 "맡기기 → 결과 받기" 두 번으로 나뉨. 실패한 요청만 다시(지금 Breaker 규칙 그대로).
4. **검증(돈 쓰기 전에)** — 사람이 이미 검수한 책 60권(제 칸 40 + 일부러 다른 칸으로 넣은 20)으로 새 지시문을 돌려 **칸 정확도 ≥ 95%**, 태그 일치율이 지금보다 낮지 않은지. 비용 약 $1. 못 미치면 멈추고 보고.
5. **버린 189권 다시** → 검수 페이지 → 사용자 검수 → 반영(`books:import`).
6. 모자라면 새 후보(하루 100권 규칙 그대로).

## 바꾸지 않는 것
추천 규칙 · 앱 화면 · 이벤트(taxonomy 변경 없음) · 정의서 기준(칸을 고르는 방식만 바뀜, 기준은 사람이 정한 그대로) · 한 줄 규칙 · YES24 글은 저장하지 않음.
