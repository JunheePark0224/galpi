# 휴대폰 뒤로가기 — 갈피 안에서 한 단계씩 (10-08, 사용자 승인)

## 왜
갈피는 한 페이지 앱이라 단계가 바뀌어도 주소가 그대로다. 휴대폰(안드로이드) 뒤로가기를 누르면 브라우저가 이전 사이트로 나가거나 닫혀서 하던 판이 날아간다 (사용자 10-08: "편의성면에서 중요").

## 동작 (사용자 승인 표)

| 지금 | 뒤로가기 |
|---|---|
| 질문 (두 번째부터) | 이전 질문 — [← 이전 질문]과 같음, E-33 `source: device_back` |
| 첫 질문 | 홈 — E-20 `source: device_back` |
| 닫힌 책 · 첫 장 | 마지막 질문 — [← 질문으로 돌아가기]와 같음, E-33 `source: device_back` |
| 책갈피 넘기는 중 · 뒤표지 | 머무름 + 안내 "책갈피는 되돌릴 수 없어요 · 처음으로 가려면 한 번 더 눌러 주세요", 3초 안에 한 번 더 → 홈 (E-20 `device_back`) |
| 궁금해요 책 정보 | 2권째부터 이전 책, 1권째면 뒤표지 |
| 마무리 | 뒤표지 |
| 홈 | 브라우저 그대로 (사이트 밖) |
| 공유 시트 · 로그인 창 · 우체통 | 그 창만 닫기 |

책갈피는 되돌리지 않는다: 반응은 이미 기록됐고 다음 책갈피도 그걸로 정해져서, 되돌리면 기록과 화면이 어긋난다.

## 구조
- `lib/nav/deviceBack.ts` — 방문 기록 한 칸 = 처리기 하나. `holdBack(handler)`가 `history.pushState`로 칸을 쌓고, `popstate`가 오면 맨 위 처리기를 부른다. 화면 버튼으로 닫힌 창은 `release()` — 자기 칸을 `history.back()`으로 거둔다(그 popstate는 건너뜀).
- `lib/flow/back.ts` — `deviceBackMove(state)`: 지금 단계에서 뒤로가기가 할 일 (순수 함수, 테스트).
- `lib/flow/state.ts` — 새 동작 `returnToBack` (궁금해요 책 정보 1권째 · 마무리 → 뒤표지).
- `Flow.tsx` — 홈이 아닌 동안 칸 하나를 지킨다(누르면 이동 후 다시 쌓음, 홈이면 안 쌓음). 머무름 안내는 화면 아래 작은 알림.
- 시트들(공유 · 로그인 · 우체통) — 열릴 때 칸 하나, 뒤로가기면 닫힘.

## 이벤트 (rule 3-1)
E-33 `question_back_clicked.source` += `device_back`, E-20 `home_clicked.source` += `device_back` — taxonomy.md → csv → schema.ts → 테스트 → track() 같은 커밋. 모으는 정보는 그대로(값 하나 추가) — 처리방침 변경 없음.

## 완료 기준
단위 테스트(이동 표 전부, 칸 쌓기·거두기), e2e: 폰 뒤로가기(`page.goBack()`)로 질문 → 이전 질문, 첫 장 → 질문, 책갈피 중 머무름 + 두 번이면 홈, 공유 시트 닫힘, 홈에서는 사이트 밖.
