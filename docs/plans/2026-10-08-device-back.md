# 휴대폰 뒤로가기 — 갈피 안에서 한 단계씩 (10-08, 사용자 승인)

## 왜
갈피는 한 페이지 앱이라 단계가 바뀌어도 주소가 그대로다. 휴대폰(안드로이드) 뒤로가기를 누르면 브라우저가 이전 사이트로 나가거나 닫혀서 하던 판이 날아간다 (사용자 10-08: "편의성면에서 중요").

## 동작 (사용자 승인 표)

| 지금 | 뒤로가기 |
|---|---|
| 질문 (두 번째부터) | 이전 질문 — [← 이전 질문]과 같음, E-33 `source: device_back` |
| 첫 질문 | 홈 — E-20 `source: device_back` |
| 닫힌 책 · 첫 장 | 마지막 질문 — [← 질문으로 돌아가기]와 같음, E-33 `source: device_back` |
| 책갈피 넘기는 중 · 뒤표지 | 머무름 + 안내 "책갈피는 되돌릴 수 없어요" [처음으로] → 홈 (E-20 `device_back`) — 10-08 고침, 아래 |
| 궁금해요 책 정보 | 2권째부터 이전 책, 1권째면 뒤표지 |
| 마무리 | 뒤표지 |
| 홈 | 브라우저 그대로 (사이트 밖) |
| 공유 시트 · 로그인 창 · 우체통 | 그 창만 닫기 |

책갈피는 되돌리지 않는다: 반응은 이미 기록됐고 다음 책갈피도 그걸로 정해져서, 되돌리면 기록과 화면이 어긋난다.

## 구조
- `lib/nav/deviceBack.ts` — 방문 기록 한 칸 = 처리기 하나. `holdBack(handler)`가 `history.pushState`로 칸을 쌓고, `popstate`가 오면 맨 위 처리기를 부른다. 화면 버튼으로 닫힌 창은 `release()` — 자기 칸을 `history.back()`으로 거둔다(그 popstate는 건너뜀).
- `lib/flow/back.ts` — `deviceBackMove(state)`: 지금 단계에서 뒤로가기가 할 일 (순수 함수, 테스트).
- `lib/flow/state.ts` — 새 동작 `returnToBack` (궁금해요 책 정보 1권째 · 마무리 → 뒤표지).
- `Flow.tsx` — 앞으로 가는 탭마다 `advance()`로 한 칸(아래 "10-08 고침"), S-01로 돌아오면 `unwind()`. 머무름 안내는 화면 아래 작은 알림 + [처음으로].
- 시트들(공유 · 로그인 · 우체통) — 열릴 때 칸 하나, 뒤로가기면 닫힘.

## 이벤트 (rule 3-1)
E-33 `question_back_clicked.source` += `device_back`, E-20 `home_clicked.source` += `device_back` — taxonomy.md → csv → schema.ts → 테스트 → track() 같은 커밋. 모으는 정보는 그대로(값 하나 추가) — 처리방침 변경 없음.

## 완료 기준
단위 테스트(이동 표 전부, 칸 쌓기·거두기), e2e: 폰 뒤로가기(`page.goBack()`)로 질문 → 이전 질문, 첫 장 → 질문, 책갈피 중 머무름 + 안내 [처음으로], 공유 시트 닫힘, 홈에서는 사이트 밖.

## 10-08 고침 — 두 번째 뒤로가기에서 꺼짐 (사용자, 폰)
처음 판은 홈이 아닌 동안 표시된 칸 하나를 지키고, 뒤로가기 뒤에 **자동으로** 다시 쌓았다. 크롬은 페이지가 누르지 않고 쌓은 기록을 뒤로가기 함정으로 보고, 그 앞 칸을 건너뛰게 표시한다(history manipulation intervention) — 그래서 첫 번째만 되고 다음부터는 사이트 밖으로 나갔다. 연달아 눌러도 마찬가지.
고친 판: **앞으로 가는 탭마다 그 탭 안에서 한 칸**(`advance` — 시작·답·펼치기·다음 장·책 정보 보기·다음 책·다시 뽑기), 뒤로가기 뒤에는 쌓지 않는다. 칸마다 깊이(`galpiDepth`)를 실어, 깊이가 줄어든 popstate만 뒤로가기로 본다(앞으로가기는 따라가기만). S-01로 돌아오면 남은 칸을 한 번에 건너간다(`unwind`). 책갈피·뒤표지의 "한 번 더 누르면 처음으로"는 칸을 새로 쌓아야 해서 크롬에서 지킬 수 없음 → 안내에 [처음으로] 버튼.
e2e는 크롬의 그 규칙을 적용하지 않아 테스트가 통과했었다. 그래서 원인을 직접 잰다: 뒤로가기 뒤 탭 없이 쌓인 칸이 0개인지(`device-back.spec.ts`) — 첫 판으로 돌리면 실패하는 것을 확인.
