# 🎯 입력 화면 설계 — v0.2 (2026-09-29)

PRD F-02 · F-05 · D-02. v0.1(질문 3개를 하나씩)은 **보기에 없는 사람이 이탈**하는 문제로 폐기.

## 1. 화면 — 한 화면에 칸 채우기

| 칸 | 필수 | 입력 |
|---|---|---|
| 무엇을 알고 싶어요 | **필수** | 보기 6개(데이터 분석 · 통계 · AI 똑똑하게 쓰기 · 업무 자동화 · 습관·집중 · 시간·생산성) 또는 **직접 쓰기**(30자, 예시 문구 "SQL, 엑셀 함수, 번아웃, 발표 준비 …" — 주제뿐 아니라 고민·상황도 적어도 된다는 신호). 칸 아래 작은 안내: **"주제나 고민을 적어 주세요 · 제목·작가로 찾을 땐 예스24 검색을 이용해 주세요 ↗"**(예스24 검색 링크, 새 탭, 로고 없이 글자만 — 품질 평가 표현("더 정확해요")은 추천·광고로 보일 수 있어 뺌) — 갈피는 아는 책을 찾는 곳이 아니라서, 칠 사람이 보는 자리에서만 기대를 맞춘다 |
| 분량 | 선택 | 얇게 · 보통 · 두꺼워도 좋아요 (YES24 쪽수로 계산) |
| 읽는 방식 | 선택 | 개념부터 쉽게 · 따라 하며 실습 (바로 써먹기) · 사례로 술술 |

비운 칸은 "상관없음". [책 펼치기]는 "무엇을"이 비어 있으면 그 자리에 안내를 띄우고 멈춘다.

## 1-2. 수준 — 삭제 (09-29)

**D2b 결과**: 2단계(입문/기초 이상)로 다시 체크 → 일치 8/10(κ0.41). 사람 입문 7·AI 입문 9 — 베스트·스테디셀러에서 온 책은 대부분 누구나 읽을 수 있어서 **수준이 책을 거의 가르지 못한다**. 엇갈린 2권은 교양서·실무서라 판단 자체가 애매. → 입력 칸의 자격(추천을 바꾸는가 · 태그가 믿을 만한가 · 이탈을 늘리지 않는가)을 못 채워 **삭제**. 심화서가 늘면(D-07) "더 깊이 알고 싶어요" 하나로 다시 검토

### (기록) 삭제 전 설계

D2 체크에서 사용자가 "조금 알아요"를 한 번도 고르지 않았고(처음 6 · 실무 4), AI와 엇갈린 수준 3건 중 2건이 그 칸이었다(κ 0.44). 원인: **지식(처음/기초)과 상황(실무에 쓴다)이 한 줄에 섞여 있었다** — 실무자도 그 주제는 처음일 수 있다.

| | 이용자 질문 "이 주제, 얼마나 알아요?" | 책 태그 | 책을 판단하는 기준 |
|---|---|---|---|
| 1 | 처음이에요 | **입문** | 사전 지식 없이 시작할 수 있다 — "입문자·비전공자·처음·기초부터", 첫 장이 개념 소개 |
| 2 | 기초는 알아요 | **기초 이상** | 기본 개념·문법을 안다고 가정한다 — "심화·실전 프로젝트", 배운 개념 정리·응용 |

- 판단 질문은 하나: **"이 책을 읽으려면 미리 알아야 하는 게 있나?"**
- "실무에 쓰고 싶다"는 읽는 방식 **"따라 하며 실습 (바로 써먹기)"** 가 담는다

## 2. 태그 — 3층 구조

| 층 | 개수 | 책에 붙이는 방식 | 예 |
|---|---|---|---|
| 분야 | 3 | 책마다 1개 | 데이터·통계 |
| 주제 | 6 | 책마다 1개 | 데이터 분석 |
| **세부 키워드** | 정해진 목록 안에서 (예상 40~60개) | 책마다 **2~5개** | SQL · 파이썬 · 엑셀 · 시각화 · 회귀분석 · 프롬프트 · 노션 · 루틴 … |

- 세부 키워드의 재료는 **YES24 제목·책소개·목차** (09-29 변경 — 정보나루 키워드는 대출 기록이 있는 책에만 있어 🎯 후보 약 150권 중 78권이 없었다). 키워드마다 정해진 이름 + 동의어 규칙으로 찾고(`src/build_vocab.py`), 없는 말을 지어내지 않는다
- **v1 목록 (09-29, 검토 후 v1.1로 대체)**: 27개 — 데이터 분석(SQL·시각화), 통계(기초 통계·확률·회귀분석·가설검정·통계적 사고), AI 활용(챗GPT·클로드·제미나이·프롬프트·바이브 코딩·AI 에이전트·이미지·영상 생성·LLM 원리), 업무 자동화(엑셀·파이썬 자동화·코파일럿·M365·AI 업무 활용), 습관·집중(습관·집중력·도파민·뇌과학·마음·회복), 시간·생산성(시간 관리·계획·목표·일하는 법). 5권 미만이라 합친 것: 파이썬·엑셀·R·데이터 리터러시(데이터 분석), 베이즈·파이썬·R 통계, 노션·구글 워크스페이스, 메모·기록·지식 관리·아침·새벽
- **키워드는 규칙이 먼저** (09-29, D2 결과): 사람↔규칙 κ 0.79 · 사람↔AI κ 0.54, AI가 엇갈린 9건 중 8건에서 더 많이 붙임 → D3에서 규칙이 초안, AI는 규칙이 놓친 것만 제안, 확정은 사람
- 키워드 목록은 **닫힌 목록**(정해진 단어만 사용) — 같은 뜻을 다른 말로 쓰는 일(예: "파이선", "Python")을 막는다

- **v1.1 (09-29, 코드 검토 반영)**: 맨 단어(시간·사고·뇌·분포·커서)가 거의 모든 책에 걸려 **복합어로 좁히고, 책의 60% 넘게 붙는 키워드는 제외** → **20개**: 데이터 분석(SQL), 통계(기초 통계·확률·회귀분석·가설검정), AI 활용(챗GPT·클로드·제미나이·프롬프트 엔지니어링·바이브 코딩·AI 에이전트·이미지·영상 생성), 업무 자동화(파이썬 자동화·코파일럿·M365·AI 업무 활용), 습관·집중(습관·집중력·뇌과학·마음·회복), 시간·생산성(일하는 법). 너무 흔해 뺀 것: 시각화(데이터 분석 11/17), 엑셀(업무 자동화 12/17). 데이터 분석·시간·생산성은 키워드가 1개뿐 — 책이 늘면(D-07) 합친 키워드가 5권을 넘어 다시 분리된다

### 얼마나 잘게 나눌지 — 기준

| 기준 | 규칙 | 이유 |
|---|---|---|
| 최소·최대 권수 | 세부 키워드 하나에 **책 5권 이상, 주제 책의 60% 이하**. 모자라면 위 층(주제)으로 합치고, 넘치면 책을 가르지 못하므로 뺀다 | 추천 4권 + 다시 뽑기를 채우려면. 너무 잘게 나누면 빈 칸만 늘어난다 |
| 태그 일치율 | 책 20권을 LLM과 사용자가 **따로** 태그(사용자는 AI 답을 보지 않고 체크 화면에서 소개 3줄·목차 요약을 보고 키워드 체크, 20~40분). **일치율(코헨 카파)** 이 낮은 키워드는 뜻을 글로 정의해 LLM 지시문에 넣거나 합친다 | 태그가 사람마다 다르게 붙으면 세분화가 의미 없다 (09-29 확정) |
| 요청 적중률 | 1단계에서 직접 쓰기 요청 중 **세부 키워드에 연결된 비율** | 사람들이 실제로 찾는 단위로 나뉘었는지 |

책이 늘어나면(D-07) 5권 기준을 넘는 키워드가 늘어나므로, **세분화는 책 수에 따라 자동으로 깊어진다.**

## 3. 직접 쓰기 → 책 연결

1. 서버가 LLM(Claude Haiku)에게 적은 말을 주고 **우리 주제 6개 + 세부 키워드 목록 중에서만** 고르게 한다 (JSON, 목록 밖 답은 버림). 추천 자체는 여전히 우리 점수 규칙
2. 3초 안에 답이 없거나 실패하면 → 제목·키워드 단어 매칭으로 대체
3. 연결된 책 수에 따라 첫 장에 **솔직하게** 말한다

| 찾은 책 | 첫 장 안내 | 책갈피 채우기 |
|---|---|---|
| 4권 이상 | (안내 없음) | 평소대로 |
| 1~3권 | "SQL 책은 아직 **2권**이에요. 나머지는 가까운 '데이터 분석' 책이에요" | 찾은 책 + 같은 주제 책 |
| 0권 | "아직 이 주제 책이 없어요. 가장 가까운 '데이터 분석' 책을 펼칠게요" + [다시 쓰기] | 가장 가까운 주제 책 |

## 4. 점수

| 항목 | 규칙 |
|---|---|
| 주제 | 일치 필수. 부족하면 같은 분야의 다른 주제로 넓힌다 |
| 세부 키워드 | 겹치는 키워드 1개당 +3 (직접 쓰기로 키워드가 잡혔을 때) |
| 분량 | 얇게: ≤250쪽 +2, ≥400쪽 −1 / 두꺼워도 좋아요: ≥300쪽 +1 (선택했을 때만) |
| 읽는 방식 | 같으면 +2 (선택했을 때만) |

상위 4권(동점 무작위) + 같은 분야 안에서 무작위 1권. 무작위 책은 겉모습 동일, 기록에만 `추천/무작위`.

## 5. 기록 추가 (PRD 4절)

| 이벤트 | 속성 |
|---|---|
| `goal_free_written` | 적은 내용(30자), 연결된 주제·키워드, LLM/단어 매칭 중 무엇으로 연결했나 |
